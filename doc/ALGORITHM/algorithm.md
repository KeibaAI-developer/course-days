# 芝コース日数アルゴリズム

## 1. 概要

本稿では、芝レースの施行日について「その芝コースが使用開始から何日目・何週目にあたるか」を表す**芝コース日数**（芝コース日目・芝コース初日・芝コース経過日数・芝コース週目の4値）の算出アルゴリズムを定式化する。

中央競馬の芝コースは、同一開催中に内柵の位置（コース区分A〜E）を移動させながら使い回される。同じコース区分が連続して使われるほど内側の芝が傷み、トラックバイアス（枠順や脚質の有利不利）が変化する。芝コース日数はこの「コースの使い込まれ具合」を表す指標であり、[course-advantage](https://github.com/KeibaAI-developer/course-advantage) がコースキーの週目として、[basic-feature-value](https://github.com/KeibaAI-developer/basic-feature-value) がレース情報系の特徴量として利用する。

芝コース日数は**レース単位ではなく「競馬場・開催日・コース区分」で決まる値**である。同じ開催日の芝レースはすべて同じ値を持つ。

本アルゴリズムの骨子は次の2段階からなる。

1. **遡及（同一コースの開催日の収集）**: 対象の開催日から過去に向かって開催スケジュールを辿り、同一競馬場・同一コース区分で行われた開催日を、コースの使用が途切れるまで収集する。
2. **集計**: 収集した開催日の並びから4値を算出する。

計算結果はKeibaAIのDBへ保存し、2回目以降は読むだけで済ませる（[getters.md](../API/getters.md)）。

## 2. 記号の定義

| 記号 | 意味 |
|---|---|
| $v$ | 競馬場（競馬場コード） |
| $c$ | コース区分（A〜E） |
| $d_0$ | 対象レースの開催日 |
| $D(v)$ | 競馬場 $v$ で開催が行われた日の集合（開催スケジュールから得る） |
| $c(v, d)$ | 競馬場 $v$ の開催日 $d$ における芝コース区分。その日に芝レースが無い場合は未定義 |
| $d_1 > d_2 > \dots$ | $d_0$ より前で $c(v, d_i) = c$ を満たす開催日を新しい順に並べたもの |
| $G$ | リセット判定の間隔（既定値 $14$ 日） |
| $W$ | 同一週判定の間隔（既定値 $2$ 日） |
| $L$ | 遡及の上限（既定値 $365$ 日） |

## 3. アルゴリズムの定式化

### 3.1 開催日のコース区分

開催日 $d$ のコース区分 $c(v, d)$ は、その日の芝レースのレース基本情報から得る。芝コースのコース区分は競馬場・開催日単位で共通であるため、**1レース分の情報で判定できる**。レース番号1〜12のレースコードを組み立て、レース番号の小さい順に見て最初に見つかった芝レースのコース区分を採用する。

- 芝レースが1つも無い開催日（ダートのみ・障害のみ）は $c(v, d)$ を未定義とし、収集の対象にしない
- 開催日に存在しないレース番号（欠番）は読み飛ばす

### 3.2 遡及

$d_0$ から過去に向かって $D(v)$ を新しい順に辿り、$c(v, d) = c$ を満たす開催日を収集する。**辿っている開催日（コース区分を問わない）と直近に収集した開催日との間隔が $G$ 日以上空いた時点で、コースの使用がリセットされたとみなして遡及を終了する。** 直近に収集した開催日の初期値は $d_0$ 自身である。

コース区分の異なる開催日は収集せず読み飛ばすだけで、基準となる「直近に収集した開催日」を動かさない。したがって終了条件は同一コース区分の開催日だけで見ても同じであり、$d_1, d_2, \dots$ を上記のとおり新しい順に並べたとき、

$$
n = \min \{ i \ge 0 \mid d_i - d_{i+1} \ge G \}
$$

とし（$d_i - d_{i+1}$ は日数差、$i = 0$ のときは $d_0 - d_1$）、$d_1, \dots, d_n$ を収集する。条件を満たす $i$ が無ければ、$D(v)$ を遡れる範囲すべてが対象になる。

ただし遡及が $d_0 - L$ を超えた場合は `LookbackLimitExceededError` を送出する。同一コースの使用が1年以上途切れないことは無く、データの不整合か判定条件の誤りが疑われるため、黙って打ち切らない。

開催スケジュールは $S = 14$ 日ずつの窓で取得し、窓の中の開催日を新しい順に処理する。窓を跨いでも判定は変わらない。

### 3.3 集計

収集した開催日に $d_0$ 自身を加えて昇順に並べたものを $e_1 < e_2 < \dots < e_m$（$e_m = d_0$、$m = n + 1$）とする。4値は次のとおり。

| 値 | 定義 | 意味 |
|---|---|---|
| 芝コース日目 | $m$ | 使用開始から数えて何日目の開催か（$d_0$ を含む） |
| 芝コース初日 | $e_1$ | 使用開始の開催日（YYYYMMDD） |
| 芝コース経過日数 | $(d_0 - e_1) + 1$ | 使用開始日から $d_0$ までの暦日数（初日当日 $= 1$） |
| 芝コース週目 | $1 + \#\{ i \mid e_{i+1} - e_i > W \}$ | 開催日の並びのうち、間隔が $W$ 日を超える箇所の数 $+ 1$ |

芝コース週目は「土日の2日開催」を1週とみなす定義である。連続する開催日の間隔が $W = 2$ 日以下（土曜→日曜、あるいは3日連続開催）なら同じ週、それを超えれば次の週と数える。

### 3.4 対象外のレース

次の場合は4値を計算せず、欠損値（`NA`）とする。

- ダートレース・障害レース（`芝ダ` が `芝` でない）
- コース区分が不明（`コース区分` が `NA`）

対象外のレースでも戻り値には4カラムが**欠損値で必ず含まれる**（[calculator.md](../API/calculator.md) の `apply_missing_course_days`）。呼び出し側は芝かどうかを気にせず4カラムを読める。

## 4. 計算例

東京競馬場（$v = 05$）、コース区分A、対象日 $d_0 = $ 2025年6月8日（日）とし、$D(05)$ のうち直近の開催日とコース区分が次のとおりだったとする。

| 開催日 | 曜日 | $c(05, d)$ |
|---|---|---|
| 2025-06-08 | 日 | A（$d_0$） |
| 2025-06-07 | 土 | A |
| 2025-06-01 | 日 | A |
| 2025-05-31 | 土 | A |
| 2025-05-25 | 日 | A |
| 2025-05-24 | 土 | A |
| 2025-05-18 | 日 | C |
| 2025-05-17 | 土 | C |
| 2025-05-11 | 日 | C |
| 2025-05-10 | 土 | C |
| 2025-05-04 | 日 | B |

遡及は 05-24 を収集したあと 05-18・05-17・05-11・05-10 を見るが、いずれもコース区分がCなので読み飛ばす（05-24 との間隔は最大でも 14 日未満）。次の 05-04 は 05-24 から 20 日離れており $G = 14$ 日以上なので、コース区分を見ずに終了する。収集結果は $e = (05\text{-}24, 05\text{-}25, 05\text{-}31, 06\text{-}01, 06\text{-}07, 06\text{-}08)$ で、

| 値 | 結果 |
|---|---|
| 芝コース日目 | $6$ |
| 芝コース初日 | `20250524` |
| 芝コース経過日数 | $(06\text{-}08 - 05\text{-}24) + 1 = 16$ |
| 芝コース週目 | 間隔が2日を超えるのは 05-25→05-31 と 06-01→06-07 の2箇所なので $3$ |

## 5. 設計上の要点

- **レース単位ではなく開催日単位で保存する**: 4値は「競馬場・開催日・コース区分」で決まるため、DBにはこの組を主キーとして1行だけ持つ。レースごとに複製すると同じ値が12行並ぶ。
- **リーク防止**: 使うのは $d_0$ より前の開催日と $d_0$ の開催有無だけで、レースの結果は参照しない。予測用特徴量としてそのまま利用できる。
- **移植元との同一性**: 本アルゴリズムは keiba-data-interface から移植したものであり、定数（$G, W, L, S$）と計算式は変えていない。移植前後で同じレースに対する4値が一致することを実データで検証済み。
- **未保存でも動く**: 予測は当日のレースを対象にするため、バッチが回る前の開催日は必ず未保存になる。取得APIは未保存なら計算して保存し、例外にしない（[getters.md](../API/getters.md)）。
