# getters.py

## `get_course_days()`

### 概要

芝コース日数4カラム（芝コース日目・芝コース初日・芝コース経過日数・芝コース週目）を設定したレース基本情報を返します。
呼び出し側はこの関数だけを使えばよく、計算するか保存値を読むかを意識しません。

処理の流れは次のとおりです。

1. 芝レースでない、またはコース区分が不明なら4カラムを欠損値で設定して返す（DBを引かない）
2. メモリキャッシュ（`cache`）にあればそれを使う
3. `course_days` テーブルを引く
4. 保存されていればその値を設定して返す
5. 保存されていなければ計算し、保存してから返す

5は例外にしません。
予測は当日のレースを対象にするため、バッチ（[computer.md](./computer.md)）が回る前の開催日は必ず未保存になり、ここで例外にすると予測が実行できないためです。
計算そのものが失敗した場合は例外をそのまま伝播させます。
未保存だったことは `INFO` ログに残ります。

`course_days` テーブルが存在することが前提です。
テーブルの作成は `CourseDaysStore.setup()` かバッチの役割で、取得ではDDLを実行しません。

### 引数

| 引数 | 型 | デフォルト値 | 説明 |
|---|---|---|---|
| `race_basic_info` | `pd.DataFrame` | - | レース基本情報（1行）。`レースコード`・`競馬場コード`・`開催年`・`開催月日`・`芝ダ`・`コース区分` を参照する |
| `data_interface` | `DataInterface` | - | 未保存だった場合の計算に使う。開催スケジュールとレース基本情報を取得する |
| `db_client` | `DbClient` | - | `course_days` テーブルへ接続するクライアント |
| `logger` | `logging.Logger \| None` | `None` | ロガー。省略時は `__name__` ベースのロガーを使用 |
| `cache` | `CourseDaysCache \| None` | `None` | 読み出した値・計算した値のメモリキャッシュ。省略時は呼び出しのたびにDBを引く |

### 返り値

入力の `race_basic_info` のコピーに4カラムを設定したDataFrame（1行）。
入力は変更しません。

| カラム名 | 型 | 説明 |
|---|---|---|
| （入力のカラム） | — | `race_basic_info` のカラムをそのまま保持 |
| `芝コース日目` | `Int64` | 同一競馬場・同一コース区分の芝コースが使用開始から何日目（開催日単位）か。対象外のレースは `NA` |
| `芝コース初日` | `object` | 当該コースの使用開始日（YYYYMMDD形式の文字列）。対象外のレースは `NA` |
| `芝コース経過日数` | `Int64` | 使用開始日からの暦日数 + 1（初日当日 = 1）。対象外のレースは `NA` |
| `芝コース週目` | `Int64` | 当該コースの使用何週目か。対象外のレースは `NA` |

対象外のレース（ダート・障害・コース区分不明）でも4カラムは必ず含まれ、dtypeも対象のレースと同じです。

### 補足

保存に失敗した場合はキャッシュへ入れません。
入れると次回以降DBを見ずに未保存の値を返し、保存の失敗が隠れるためです。

### 例外

| 例外 | 条件 |
|---|---|
| `LookbackLimitExceededError` | 未保存で計算した際、過去開催日の遡及が上限（365日）を超えた場合 |
